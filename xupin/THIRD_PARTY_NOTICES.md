This app's static pinyin dictionary is derived from two files in rime-ice's `cn_dicts/` tier:

- `cn_dicts/8105.dict.yaml` — single-character table (《通用规范汉字表》8105 字), used in full
  (8,652 entries). Kept whole because every legal pinyin syllable needs at least one
  single-character fallback candidate.
- `cn_dicts/base.dict.yaml` — general word list (542,928 entries). **Only the top 200,000
  entries by rime-ice's own static weight are kept**; see "Why the word list is trimmed" below.

Explicitly **not** used: `cn_dicts/ext.dict.yaml`, `cn_dicts/tencent.dict.yaml`,
`cn_dicts/others.dict.yaml` — rime-ice's own docs mark these as supplementary/expansion tiers on
top of `base`, not part of the "basic" word set; out of proportion for this v1 static-only issue.

### Derived asset

- `entry/src/main/resources/rawfile/dict/words.dict.tsv` — regenerated from the two source files
  above by `tools/build-dict.py`. Format: `pinyinKey\tword\tweight` per line, grouped by key,
  weight-descending within a group. `pinyinKey` is the word's pinyin syllables concatenated
  without spaces or tone marks (rime-ice's own dictionary key convention).
- `entry/src/main/ets/pinyin/syllables.ets` — the set of 414 legal pinyin syllables, derived from
  the union of syllables appearing in the two source files (i.e. every syllable in this table is
  guaranteed to have dictionary backing). Regenerated by the same script.

To regenerate: run `python3 tools/build-dict.py` from `xupin/` after placing rime-ice's
`8105.dict.yaml` and `base.dict.yaml` (at the pinned commit above) under
`tools/rime-ice-src/cn_dicts/`. See the script header for exact source URLs.

### Why the word list is trimmed to 200,000 entries

The full `base.dict.yaml` (542,928 word entries) parses into an in-memory
`Map<pinyinKey, Array<[word, weight]>>` costing roughly **154 MB** of heap (measured empirically
in Node — see PR #5 discussion for the measurement). No documented per-process memory ceiling for
`InputMethodExtensionAbility` was found in the local HarmonyOS docs corpus, but that is still an
unreasonable footprint for an IME extension process running alongside other apps on a phone.
Keeping the top 200,000 entries by weight (weight cutoff ≈ 1760) costs ~58 MB instead, while still
covering every common daily word checked during development, including product-relevant terms
like 鸿蒙 (weight 3005, would have been dropped at a 100k cutoff). This is a static-frequency cut
using rime-ice's own weight field — not an arbitrary truncation — and is orthogonal to the ADR-0002
personal-layer privacy-pruning constraints (those govern the *personal* usage-history layer, not
this static base dictionary).

Consequence: a small number of low-frequency words/proper nouns (weight < ~1760) will not appear
as whole-word candidates; users can still type them character-by-character via the 8105 table.

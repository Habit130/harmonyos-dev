# 词典数据来源定为雾凇拼音(rime-ice),应用整体协议定 GPL-3.0

**Status: accepted**

## 背景

拼音预测输入法(见 `CONTEXT.md`)需要一份拼音→字/词的词典数据(定义候选词全集,配套静态频率权重),这是[候选词生成](../../CONTEXT.md)阶段的地基,不是预测模型本身(参见 CONTEXT.md 中"词典数据"与"训练语料"的区分)。

调研了几个候选数据源:CC-CEDICT(CC BY-SA,允许商用,但是通用双语词典,没有词频)、THUOCL(允许商用,含 DF 频率值,但数据基于 2017 年语料,较旧)、雾凇拼音/rime-ice(GPL-3.0-only,专为拼音输入法设计,长期维护,含词频调权,内容和格式都更贴合需求)、libpinyin/sunpinyin(GPLv2+,统计语言模型引擎而非纯词典)。

最初倾向排除 GPL 数据源,因为 GPL 强 copyleft——一旦分发物中包含 GPL 数据,整个分发包实际上要按 GPL 条款走(必须提供对应源码、衍生作品需 GPL 兼容协议),这对一个原本可能保持任意协议的项目是一个强加的外部约束。但确认了这个 App 本来就计划开源(仓库本身也已经是 public),这个约束不再是代价。

## 决定

1. 词典数据源采用**雾凇拼音(rime-ice)**,CC-CEDICT / THUOCL 作为交叉校验/补充来源。
2. 应用整体协议定为 **GPL-3.0**(不是"自己的代码挂宽松协议、数据单独挂 GPL"这种拼接——GPL-3.0 数据一旦纳入分发物,整体分发就要满足 GPL-3.0 条款,因此直接把整个应用的协议定为 GPL-3.0,而不是制造一个名义上独立、实际不成立的协议分层)。

## 为什么

- 雾凇拼音是专门为拼音输入法场景设计和维护的词库(含双字词调频、腾讯大词库注音、emoji、英文词库),内容和格式都比通用双语词典(CC-CEDICT)更贴合这个项目的实际需求,规模也更大("百万级中英词库")。
- 一旦接受 GPL 数据源,试图让自己的原创代码挂一个"更宽松"的协议(如 MIT)是没有意义的——分发物作为整体仍然受 GPL-3.0 约束,伪装出协议分层只会制造后续维护者的困惑,不如从一开始就统一定为 GPL-3.0,诚实反映真实的分发条款。
- 该决定的前提(GPL 约束不再是代价)成立的原因是这个项目和仓库本身已经确定要开源(见仓库根 `CLAUDE.md` 关于仓库定位的说明,以及本仓库 GitHub 远端已是 public),因此没有"必须保留闭源可能性"这个诉求需要权衡。
